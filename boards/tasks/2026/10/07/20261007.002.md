# Description
Initialize the Go module with the vanity URL `gotcode.org/sourcevault` and
scaffold the core two-binary application structure according to the
architecture rules.

# Acceptance Criteria
- [x] Go module initialized (`go.mod` and `go.sum`)
- [x] Cobra CLI scaffolded for `cmd/sourcevaultd`
- [x] Cobra CLI scaffolded for `cmd/sourcevault`
- [x] `Makefile` includes `tidy`, `lint`, `sec`, and `check` targets
- [x] Verified locally via `make check`

# Implementation Plan
1. Run `go mod init gotcode.org/sourcevault`.
2. Add `spf13/cobra` and `github.com/charmbracelet/lipgloss` dependencies.
3. Create `internal/ui/styles.go` and `internal/ui/views.go` to override the
   default Cobra help/usage commands with customized `lipgloss` styling
   and a custom SourceVault ASCII banner.
4. Create `cmd/sourcevault/main.go` and `cmd/sourcevault/version.go`.
5. Create `cmd/sourcevaultd/main.go` and `cmd/sourcevaultd/version.go`.
   - The CLIs will inject the custom UI prompt via `cmd.SetUsageFunc()` and
     `cmd.SetHelpFunc()`.
   - The `version` commands will strictly follow Hexagonal Architecture by
     delegating data retrieval to a `GetVersionQuery` handled in the
     `internal/system` package, which relies on a `RuntimePort` interface
     implemented by `adapter_runtime.go`.
   - Output presentation is handled in `internal/ui/version.go` using
     `text/tabwriter` to print a clean ASCII table with Version, Git Commit,
     Git Branch, Go Version, OS/Arch, and embedded dependencies. The table
     omits a generic 'Header | Value' top row for a sleeker look.
6. Create an advanced `Makefile` with the following targets:
   - `tidy`: Runs `go mod tidy` and `go mod download`.
   - `lint`: Runs `golangci-lint run ./...`.
   - `sec`: Runs `gosec ./...`.
   - `check`: Chains `tidy`, `fmt`, `vet`, `lint`, `sec`, and `test`.
   - `build`: Uses Git CLI to extract tags/commits/branches and compiles the
     binaries with `-ldflags` to inject version data into `main.Version`,
     `main.Commit`, etc.
